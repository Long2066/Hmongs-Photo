# PayOS rollout checklist

This checkout is **not operational until the hosted API and Firestore rules are configured and deployed**. Do not use existing fixed PayOS links for new purchases. Keep any secrets exclusively in the host's server-side environment; do not place them in Vite variables, source files, chat, or desktop packages.

1. Deploy the Vercel API (`api/payos-create.js`, `api/payos-status.js`, `api/payos-webhook.js`) to the HTTPS host serving the frontend, with `FIREBASE_SERVICE_ACCOUNT_JSON` (restricted Firebase service account JSON for project `toolphoto-2025`), `PAYOS_CLIENT_ID`, `PAYOS_API_KEY`, `PAYOS_CHECKSUM_KEY`, `PAYOS_RETURN_URL`, and `PAYOS_CANCEL_URL`. Set HTTPS return/cancel URLs on the same origin to the frontend application; do not take URLs from checkout requests. Prefer provider-managed secret storage and least privilege.
2. In the PayOS dashboard, register and verify `https://<API_HOST>/api/payos-webhook` using its documented webhook registration flow. The endpoint validates SDK HMAC and queries PayOS again before crediting. A webhook without a known order never credits.
3. Build the desktop app with public `VITE_PAYOS_API_ORIGIN=https://<API_HOST>` (this is an API origin, **not** a credential). Firebase-hosted frontend also requires this setting when the API is deployed to a different host. Same-origin Vercel web app can omit it. If a separate Firebase-hosted frontend uses the Vercel API, configure server-only `PAYOS_FRONTEND_ORIGIN=https://<FRONTEND_HOST>` to permit that exact web origin. Electron's local HTTP server does not implement `/api/payos-*`.
4. Deploy **both** synchronized Firestore rule files, `firestore.rules` and `AdminPanel/firestore.rules`, against the intended Firebase project using the sanctioned Firebase deployment workflow. Firestore Admin SDK bypasses rules; users cannot increase balances. Test admin account access and owner-only credit reads before deploying to production.
5. Before enabling paid purchases: review and migrate old AI bill/image verification (`CreditsPurchaseModal`), quota rewards (`quotaStationService`), and older client versions; these client-side increases now fail under hardened rules. Old clients may still display old checkout URLs, so deprecate/release-update old desktop builds. Review any outstanding bills/orders; reconcile verified bank transfers manually without blindly replaying the new webhook.
6. Validate via `node --test tests/payos-core.test.js`, `npm run build`, Firestore emulator rules tests and a controlled sandbox/small-value PayOS transaction: first and second purchase, duplicate webhook, wrong amount/order/user, cancel, iframe white screen and external browser fallback. Never credit a screenshot as proof of settlement.

No real PayOS payment or Firestore rule deployment was performed by this change.
